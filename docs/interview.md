# 项目面试说明

建议先解释需求、本人实现的模块和实验边界，再讲具体技术。

## 两分钟介绍

ReelPilot 面向文娱素材的画面查找和候选剪辑。我把素材转成带来源和时间区间的窗口，分别构建画面、对白与联合内容索引。用户的创意经小模型和 Schema 约束解码变成检索目标，再由程序编译成受预算约束的剪辑计划，经过独立校验后调用 FFmpeg 执行。

实现重点是模型输出与执行之间的契约，以及可恢复的工具链。模型只决定检索什么，时间戳和命令由程序控制。SQLite 记录原始请求、阶段结果和所有权租约，恢复时检查产物哈希。

实验中发现统一融合画面与字幕会干扰画面需求，因此按目标选择检索视图，并保留融合对照。当前结果来自两份公开素材和代理辅助构造的小规模开发标签，尚无真实用户工时、独立人工测试或生产部署结果。

## 需要能回答的追问

- 为什么画面与转写不直接拼接？用消融结果说明语音内容可能与当前画面不一致，相关性和模态噪声需要分开分析。
- 为什么使用 EditPlan？它让模型目标与工具参数分离，提供稳定、可检查的执行契约。
- JSON Schema 解决了什么？解决结构和字段约束；语义、预算、来源归属仍由后续校验或人工审片处理。
- 为什么不能说 exactly once？崩溃发生在产物发布与阶段记录之间时，子进程可能再次执行；系统提供受租约约束的发布和内容验证。
- 发现过什么具体问题？初次加载嵌入检查点出现大量未加载权重；加入严格 key 检查，修正专用 backbone 包装。另发现近纯黑片尾会被极短查询召回，加入空白画面规则并重新运行开发实验。
- 为何不强调 MRR 的大幅提升？当前查询由代理辅助构造且中英文成对相关，数据量很小，适合方案调试，不足以证明泛化。
- 六秒窗口的局限是什么？中点帧会漏掉动作、快速切换及镜头边界，台词也可能被切断。下一步应在独立测试集上验证镜头切分、多帧表征和边界修正。

## 个人贡献的准确范围

可描述为实现数据管线、模型接入、模态路由、计划编译与验证、执行恢复和应用接口。基础模型来自公开检查点；项目没有进行基础模型微调、强化学习训练或企业线上部署。
