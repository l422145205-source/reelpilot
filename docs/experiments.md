# 开发实验记录

## 数据与冻结范围

使用 Tears of Steel 正片与 Sintel 预告片，共 786.375 秒。按六秒窗口组织 132 个片段，每段一个中点帧。Whisper base.en 使用 CPU int8，按词中点分配转写。没有独立的 ASR 准确率测量。

`examples/pilot_queries.json` 在首轮排名实验前编写，包含 15 个场景意图的 30 条中英文表述和相关窗口 ID。标签由代理观察带时间戳的联系表后辅助构造，没有独立人工复核；同意图两种语言并非独立样本。它适合开发调试，不是训练/验证/测试三划分的泛化评测。

模型、环境、库哈希、查询文件 SHA256、编码器 fingerprint 及每条查询前十结果均记录在 `reports/retrieval_pilot.json`。当前编码器 fingerprint 为 `80b4db32f7e6459fb37c75eee1ff0e3cd5e01863bc418b2b947f973dd60b10e9`。

## 对照方法和口径

1. BM25：仅使用转写文本。
2. dense_image：仅编码中点帧。
3. dense_text：仅编码转写。
4. dense_joint：将画面与转写放入同一嵌入输入。
5. rrf_joint：BM25 与联合向量排名做 RRF。

画面检索排除均值或标准差过低的近纯黑帧；这是简单的可用性规则，不能识别所有片尾或转场。所有向量方法使用同一个固定的公开 Qwen3-VL-Embedding-2B 检查点，不进行微调。

MRR@10 对首个相关窗口的倒数排名求均值；前十无相关结果记零。set_recall@5 是前五命中的相关窗口数量 / 标注相关窗口总数，再对查询求均值，**不是 Hit@5**。查询编码与缓存向量后的排名耗时分别计量。

| 方法 | MRR@10 | set_recall@5 |
|---|---:|---:|
| BM25 | 0.108651 | 0.062037 |
| dense_image | 0.931944 | 0.703704 |
| dense_text | 0.109114 | 0.072222 |
| dense_joint | 0.790873 | 0.600463 |
| rrf_joint | 0.600093 | 0.390741 |

查询编码 p50 30.49 ms，p95 32.87 ms，不含加载。缓存后的纯排名仅约 0.14–0.23 ms，不能作为用户端到端耗时宣传。

结果说明当前这组画面问题对字幕融合敏感，不能推广成「混合检索总是更差」。据此采用显式目标通道路由：画面走 image；对白走 text 与 BM25；混合走 joint。该决策使用了同一开发集，尚无独立测试验证；对白收益尤其未经本评测证明。

## 真实模型与媒体执行

| 运行 | 输入方式 | 计划 / 实际时长 | 核查结果 |
|---|---|---|---|
| v1-llm-trailer | 中文需求 → Qwen3-0.6B 解析 | 18 / 18.021 秒 | 生成可解码视频，预算及来源校验通过；城市目标误召回室内全息场景 |
| v1-animation | 三项明确画面目标 | 12 / 12 秒 | 山峰、小龙、沙丘分别命中三个窗口，每段取前四秒；单个中点帧不能保证整个截取片段都符合目标 |
| v1-recovery | 大脑与城市两个明确目标 | 12 / 12.021 秒 | 渲染完成后主动抛出异常，重试复用 compile/verify/render，再完成 probe |

时长允许容器与音频帧导致的小误差，代码按明确 tolerance 检查。预算是上限，并非必须铺满。

恢复实验日志包含 `failed: controlled interruption after render`，随后三条 `cache_hit`，渲染 attempts=1。该记录验证受控异常下的恢复，不是断电测试。测试套件另验证过期 owner 不能发布、相同幂等键不能换请求、缓存文件损坏后重新渲染。

## 发现与修正

- **检查点加载错误**：直接加载内部 backbone 时出现大量未加载参数。通过匹配 checkpoint 命名空间的包装器及严格 missing/unexpected/mismatched keys 校验修正，随后重建全部索引。
- **图像输入格式差异**：图像后追加空白文本与官方图像输入约定不同，修正为纯图像内容，更新 fingerprint 并重新运行所有向量和排名实验。上表只对应修正后的结果。
- **模态噪声**：画面需求与当前窗口台词不一定相关，因此保留三视图及融合对照，默认按目标路由。
- **近纯黑窗口**：部分短查询召回片尾空白，加入简单规则，但仍不能识别片尾字幕或所有无关静态场景。
- **规划扩写**：0.6B 模型虽然输出合法 JSON，仍添加 advanced technology、complex task 等未要求属性。这会改变召回；Schema 约束解决格式，不能解决忠实度。

## 验证与后续优先级

本地 CPU 测试 41 项，覆盖数据契约、无候选、路径和时间越界、计划篡改、租约竞争、失效发布、内容损坏、真实编码、恢复和 HTTP Range。GitHub Actions 在 Linux Python 3.11/3.12 执行同一套测试；实际运行状态见仓库 Actions。

后续应先建立不同片源、独立人工标注的测试集，评估需求忠实度和完整片段边界；再比较镜头切分与多帧表征。不能仅扩大代理生成查询后继续复用开发集挑方案，也不应把换一个更大模型当作已经验证的收益。
